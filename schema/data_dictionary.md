# Data Dictionary

Complete schema reference for all tables generated by the Leave & Expense
Synthetic Data Generator.

---

## employees.csv

Employee master data with org hierarchy.

| Column | Type | Format | Nullable | Unique | Description |
|--------|------|--------|----------|--------|-------------|
| `employee_id` | string | `EMP0001`–`EMP0400` | No | **PK** | Unique employee identifier |
| `first_name` | string | — | No | No | First name |
| `last_name` | string | — | No | No | Last name |
| `email` | string | `first.last.N@company.com` | No | Yes | Corporate email |
| `department` | string | One of 8 departments | No | No | Department name |
| `designation` | string | See allowed values | No | No | Job title / level |
| `cost_center_id` | string | `CC001`–`CC008` | No | No | FK → `cost_centers.cost_center_id` |
| `hire_date` | date | `YYYY-MM-DD` | No | No | Employment start date |
| `termination_date` | date | `YYYY-MM-DD` | Yes | No | Employment end date (empty = active) |
| `manager_id` | string | `EMP0001`–`EMP0400` | No | No | FK → `employees.employee_id` |

**Allowed values:**
- `department`: Engineering, Sales, Marketing, Finance, HR, Operations, Legal, Product
- `designation`: Junior Engineer, Senior Engineer, Team Lead, Manager, Senior Manager, Director, VP

## leave_policies.csv

Leave-type definitions and rules.

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `policy_id` | string | No | **PK** | `LP001`–`LP006` |
| `leave_type` | string | No | Yes | Leave category name |
| `annual_quota` | integer | No | No | Days allocated per year |
| `max_consecutive_days` | integer | No | No | Max days in a single request |
| `min_notice_days` | integer | No | No | Minimum advance notice required |
| `carry_forward` | boolean | No | No | Whether unused days carry over |
| `encashable` | boolean | No | No | Whether unused days can be encashed |

**Leave types:** Earned Leave, Sick Leave, Casual Leave, Maternity Leave, Paternity Leave, Compensatory Off

## expense_policies.csv

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `policy_id` | string | No | **PK** | `EP001`–`EP007` |
| `category` | string | No | Yes | Expense category |

| `monthly_limit` | float | No | No | Monthly category cap (INR) |

**Categories:** Travel, Meals, Accommodation, Software, Office Supplies, Training, Client Entertainment

## leave_balances.csv

Per-employee per-leave-type balance tracking for FY 2025.

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `balance_id` | string | No | **PK** | `LB00001`–`LB02400` |
| `employee_id` | string | No | No | FK → `employees.employee_id` |
| `leave_type` | string | No | No | FK → `leave_policies.leave_type` |
| `year` | integer | No | No | Fiscal year (2025) |
| `opening_balance` | integer | No | No | `accrued + carry_forward` |
| `used` | integer | No | No | Days consumed |
| `accrued` | integer | No | No | Annual quota |
| `carry_forward` | integer | No | No | Days carried from prior year |
| `remaining` | integer | No | No | `max(0, opening_balance - used)` |

**Validation rule:** `opening_balance = accrued + carry_forward`; `remaining = max(0, opening_balance - used)`

| Column | Type | Format | Nullable | Unique | Description |

| `leave_request_id` | string | `LR0001`–`LR0800` | No | **PK** | Unique request identifier |

## approval_steps.csv

Multi-level approval chain for both leave requests and expense claims.

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `approval_step_id` | string | No | **PK** | `AS00001`+ |
| `entity_type` | string | No | No | `leave_request` or `expense_claim` |
| `entity_id` | string | No | No | FK → the relevant entity table |
| `step_order` | integer | No | No | 1-based sequence within entity |
| `approver_id` | string | No | No | FK → `employees.employee_id` |
| `approver_role` | string | No | No | Role at this level |
| `status` | string | No | No | Step outcome |
| `decision_date` | date | No | No | Date of decision |
| `reason_code` | string | No | No | Machine-readable reason |

**Allowed statuses:** Approved, Rejected, Skipped  
**Sequence rule:** If step N is Rejected, all subsequent steps must be Skipped.

---

## reimbursements.csv

Processed payments for approved expense claims.

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `reimbursement_id` | string | No | **PK** | `RB0001`+ |
| `claim_id` | string | No | No | FK → `expense_claims.claim_id` |
| `employee_id` | string | No | No | FK → `employees.employee_id` |
| `amount` | float | No | No | Reimbursed amount (INR) |
| `currency` | string | No | No | `INR` |
| `status` | string | No | No | `Processed` |
| `processed_date` | date | No | No | Payment date |
| `payment_method` | string | No | No | `Bank Transfer` or `Direct Deposit` |

**Eligibility rule:** Reimbursement is only created for claims with status `Approved`.

## status_events.csv

Append-only audit trail of every status transition.

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `event_id` | string | No | **PK** | `SE000001`+ |
| `entity_type` | string | No | No | `leave_request` or `expense_claim` |
| `entity_id` | string | No | No | FK → the relevant entity table |
| `from_status` | string | No | No | Status before transition |
| `to_status` | string | No | No | Status after transition |
| `event_timestamp` | datetime | No | No | ISO 8601 timestamp |
| `actor_id` | string | No | No | FK → `employees.employee_id` |
| `reason_code` | string | Yes | No | Machine-readable reason (if applicable) |

**Chain pattern:** `Draft → Submitted → Under Review → Approved/Rejected`

## ground_truth.csv

Anomaly labels for evaluation — **not an input table**.

| Column | Type | Nullable | Unique | Description |
|--------|------|----------|--------|-------------|
| `entity_type` | string | No | No | `leave_request`, `expense_claim`, or `reimbursement` |
| `entity_id` | string | No | No | FK → the relevant entity table |
| `issue_type` | string | No | No | Anomaly scenario type |
| `description` | string | No | No | Human-readable explanation |
| `expected_decision` | string | No | No | Expected approval outcome |
| `expected_reason` | string | No | No | Expected reason code |

**Allowed issue_types:**
`missing_receipt`, `duplicate_receipt`, `policy_limit_breach`,
`overlapping_leave`, `insufficient_balance`, `self_approval`,
`expense_outside_dates`, `missing_cost_center`, `holiday_span`,
`split_claim`, `duplicate_reimbursement`
